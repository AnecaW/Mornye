# Mornye 5.4.4 — Streaming and independent libraries

- NAS playback reuses account-scoped HTTP connections. Preparation requests are shared with subscriber-specific cancellation; one cancelled caller cannot interrupt another listener or a shared metadata fetch.
- Strict bounded progressive validation remains in place: audio/MIME/error responses, redirects, authentication and byte ranges are checked. A prefix is kept separately from verified complete offline audio and metadata/artwork caches.
- Per-account latency, transfer capacity, encoded bitrate and recent preparation failures set bounded native buffering preferences. The Darwin player checks actual loaded ranges/decoder preroll before reporting prepared, has a finite deadline, and ignores replaced items.
- Timeout, authentication, missing media, invalid audio, network and player failures remain separate. Recovery is finite and generation-bound; errors shown in the UI are friendly and contain no native exception text.
- Browsing, search, Home, mixes, autoplay, playlist resolution and car media browsing use one enabled-source boundary. Turning off device scanning does not turn off NAS catalog rows. Mix caches include the selected sources. Disabled/offline sources retain their indexed data and identity.
- A capability registry describes existing sources. Advertised Subsonic API versions gate optional endpoints; missing song errors never disable a whole endpoint. SMB upload is separate from Subsonic and is never advertised as a standard Subsonic upload endpoint.
- Radio uses the existing EQ DSP. The iOS/macOS 27 mixed-output tap supports HLS, including streams without an AVAssetTrack. Older systems retain the existing per-track path and explicitly report unsupported HLS effects rather than claiming they are active.
- Existing design and navigation are preserved.

## Validation and delivery

The attached validation report is authoritative for the exact source revision, completed tests and package hashes. Native macOS tests have verified actual HLS PCM attenuation and a gain change during playback. Final iOS simulator, platform package and full-suite results are recorded in that report, not presumed from compilation.

An actual iPhone, the user's NAS, Wi-Fi interruption on hardware and older iOS radio compatibility have not been verified in this environment. An unsigned IPA requires signing before installation. Android fork packages use temporary delivery signing and may require reinstalling instead of updating an earlier differently signed fork.
